§1 · Discovered, not guessed

Exact model identifiers & live API behavior

Every model ID below came from each provider's own models-list endpoint (a free metadata call), not from memory or documentation.

Claude

claude-haiku-4-5-20251001

Cheapest, dated/pinned Claude tier — chosen for cost control and reproducibility (a rolling alias would silently point at a different model on rerun).

Gemini

gemini-2.5-flash-lite

Cheapest stable, non-preview Gemini tier — same reproducibility logic as Claude's pick.

API CHANGE
The Claude Messages API no longer accepts temperature at all (confirmed via inspect.signature on anthropic==1.9.0, not a docs mismatch). Sampling control has moved to an effort parameter (low/medium/high/xhigh/max) plus native JSON-schema structured output. Used effort="low" as the closest available lowest-variance setting, and a strict JSON-schema enum to constrain Claude's answer to a valid label. Gemini still accepts temperature=0 as specified. This asymmetry is recorded per-row in sampling_config, not silently normalized away.
NOTE
Neither model reuses ReMedQA's own prompt/prompt_think fields — those explicitly request step-by-step reasoning and a boxed final answer, which would violate the no-chain-of-thought requirement. A separate minimal prompt template (scripts/phase1a_prompts.py, version phase1a_v1) is used instead.

§3 · Pipeline validation

What the smoke test was actually for

CheckResult
Prompt formatting (no CoT, custom template)pass
Answer parsing (separate from inference, unit-tested offline first)pass
Label mapping (mcq A–D vs roman_numeral I–IV)pass
API stabilityGemini stable · Claude blocked, not unstable
Caching (no duplicate spend on rerun)pass — verified 20/20 cache hits on 2nd run
Restart behaviorpass — a schema-migration bug was caught and fixed without losing a cached result
Raw response preservationpass — full JSON per call under results/behavioral/raw/
BUG FOUND
The raw-record schema changed mid-development (a temperature field became sampling_config) after some Gemini responses were already cached under the old schema, which crashed the parse step on reload. Fixed with a backward-compatible fallback rather than deleting and re-paying for the already-cached responses — exactly the kind of failure this smoke test exists to surface before it happens at 200-question scale.
§4 · Stop condition

What happens next

STOP
Per protocol, the remaining 190 questions are not run regardless of smoke-test outcome — that requires explicit approval. Separately, the Claude half of even this smoke test cannot complete until the account usage cap resets (2026-10-01 00:00 UTC per Anthropic's own error message). Full report: results/audit/PHASE1A_SMOKE_TEST_REPORT.md.
Remaining requests, full 200-question cohort

200 originals × 2 conditions × 2 models = 800 total. 40 attempted in this smoke test (20 succeeded / Gemini, 20 blocked / Claude). 780 remain — 760 for the untouched 190 originals, plus the 20 still owed from this smoke test on Claude.

Open decision needing confirmation

Cheapest-tier models (Haiku, Flash-Lite) were used for cost control on this smoke test. Whether the actual Phase 1A science should use these same tiers or a flagship tier (Opus/Sonnet, Gemini Pro) is a separate methodological call that changes how results should be framed.
