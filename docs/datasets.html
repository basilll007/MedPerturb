LEAK
MedQA test is not independent of ReMedQA. ReMedQA's medqa_mcq (1,259 questions) is a 100% subset of local MedQA's test split. Evaluating on both as if independent double-counts almost the same 1,259 questions. train (10,178 rows) and validation are unaffected — 0% overlap — and are the correct source for a larger MedQA-based cohort.
OK
CareQA is a legitimate independent validation set. 0% exact-match overlap and 0 near-duplicate candidates against every ReMedQA source pool and all of local MedQA. Its own 38 internal duplicate-stem groups are different exam content per stem — key on unique_id, don't deduplicate by question text.
§3 · Per-dataset audit highlights

Three key decisions surfaced by the audit

Key 1 · ReMedQA parsing

options and answer columns are Python repr strings, not JSON. ast.literal_eval(row["options"]) returns the actual list/dict; json.loads will fail silently on single-quoted keys or embedded apostrophes. The audit script verifies this on every row — not a sample.

Key 2 · CareQA id column

Despite having a column literally named exam_id, that field has only 210 unique values over 5,621 rows — it groups questions by exam, not by row. The correct row key is unique_id. The 38 duplicate-stem groups (90 rows sharing a stem but having different options) are legitimate different questions, deduplicating them by text would silently drop real content.

Key 3 · MedQA position-only indexing

Local MedQA has no id column whatsoever. Any join to ReMedQA must be content-based (normalized question text) rather than id-based — which is exactly how the overlap analysis produced the 1,259/1,259 match between medqa_mcq and MedQA test. Good news: answer == options[answer_idx] was verified on 200/200 sampled rows per split, so the two columns are consistent.
