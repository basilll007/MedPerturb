§1 · Architecture

Change the adapter, not the experiment

All provider-specific code lives in src/medperturb/adapters/gemini.py. Evaluation code never sees an SDK object. The label parser reproduces the validated Phase 1 parser exactly (0 mismatches over 80 cached Phase 1 responses).

ComponentResponsibility
perturbations/registry.pyper-condition category, display, output kind, evaluator, and which paired metrics are justified
perturbations/audit.pypre-run gate against example contents and ReMedQA's own prompts; any contradiction stops execution
adapters/base.py · gemini.pygenerate(example, prompt, spec) → ModelResponse; tokens, finish reason, cost normalized
parsing/canonical.pylabel / label-set / free-text parsers; ambiguity is always a failure, never a guess

§3 · What the framework surfaced

Findings to carry forward

OPEN
The string evaluator cannot measure free-text medical answers. "Urinary catheterization" (gold: "Insert a straight cath into the bladder") and "Intravenous normal saline hydration" (gold: "Intravenous fluids") look correct but match no option. With options hidden, "Influenza A virus" is a defensible answer to a reassortment question whose MCQ gold was "Rotavirus". The framework abstains instead of mis-scoring; choosing a semantic judge is a design decision for the next phase.
IDENTITY
fixed_pos changes the answer position in 82% of pairs but the semantic answer in 2%; none_of_the_provided is the reverse (10% vs 98%, required). Metrics built on the option index alone would invert both conclusions.
CORRECTION
Phase 1 cost estimates omitted billed thinking tokens: recomputed from cached responses, Phase 1's Gemini spend was $0.0545, not $0.0097 (5.6×). Phase 2A bills thinking tokens.
§4 · Readiness

Freeze the core, not the open evaluator

Core framework is ready to freeze. Scaling to N=200 on Gemini is mechanically safe (~1,400 calls, ~$0.9). Before adding models: build and smoke-test the Claude adapter (no temperature in its API; record effort instead), and decide how open will be judged.
